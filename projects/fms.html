Overview

문제와 해결

중소 운송 업체는 ERP 도입이 어렵습니다. 업무 프로세스가 체계화되지 않아 "무엇이 필요한지"조차 설명하기 어렵기 때문입니다.

그래서 요구사항을 받아 적는 대신 직접 캐냈습니다. 현업 담당자 인터뷰, 회의 녹음 분석, 18개 엑셀 파일 역분석으로 실제 업무를 재구성하고, 4주 만에 프로덕션 수준의 ERP를 완성했습니다.

핵심은 기능 개수가 아니라 세 요소의 연결입니다. 어느 차량이, 어떤 기사와, 어느 거래처의 계약을 수행했는지 이어 붙여야 운행 한 건이 비용과 매출과 거래처별 공헌이익으로 추적됩니다. 흩어진 장부를 모아 보여주는 도구와 갈라지는 지점이 여기입니다.

그룹 3개 법인에서 실제로 돌려 검증한 뒤, 같은 문제를 겪는 다른 운수회사가 쓸 수 있도록 제품으로 다시 만들었습니다. fms.1-bus.com에서 로그인 없이 3분 데모로 의사결정 흐름을 볼 수 있습니다.

Process

개발 프로세스 (4주)

01현업 분석Week 1

담당자 인터뷰 및 회의 녹음 분석, 18개 엑셀 파일 구조 역분석, 요구사항 도출 및 우선순위 설정

02설계Week 2

DB 스키마 설계 (25+ 테이블, 818 lines), 46개 거래처명 퍼지 매칭 테이블, API 엔드포인트 설계 (30+ routes)

03핵심 개발Week 3

Next.js 14 App Router 구조, Prisma ORM + PostgreSQL (Supabase), OAuth 2.0 (Google, Kakao) + 승인 워크플로우, 다중 엑셀 ETL 파이프라인

04완성 및 배포Week 4

16+ 페이지 UI 구현, E2E 테스트 (Playwright), Vercel 배포 (readonly 모드), 문서화
